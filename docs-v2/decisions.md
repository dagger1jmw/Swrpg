## 2026-11-16 — Phase 2 architecture

Design changes made while writing docs-v2/architecture.md. "Jared" marks his direct decisions; the rest are architecture choices he approved with the Phase 2 plan.

- **D-11 Module layout.** Added `src/features/<name>/` (one FeatureModule each), `src/memory/` (retrieval logic), `scripts/build-lore.ts` and `tests/fixtures/ai/` to the proposed layout. `src/engine/` keeps only shared math and imports only `src/data/`; `src/state/` holds the registry, applyEvents and advanceTime. Layer and selector-only rules are enforced by ESLint (`no-restricted-imports`, `no-restricted-globals`); Jared approved `eslint` and `typescript-eslint` as dev dependencies, and `npm run lint` joins the done-check. *Reason:* the feature module contract and story-memory addenda need homes, and the dependency rule must be checked by a tool, not by review.
- **D-12 Event schemas live in their features.** Amends ai-events.md ("Every event is a Zod schema in src/ai/schemas/"): each event's Zod schema is defined in its owning FeatureModule; `src/ai/schemas/` only composes them. *Reason:* one owner per event, and the handler and schema change together.
- **D-13 Entity references are IDs only.** Amends ai-events.md ("known IDs or names"): the AI references stable IDs listed in the context. New entities enter only through npcIntroduced, newLocation and newItem. Unknown refs get an exact normalized alias match only (no fuzzy matching); otherwise the event is dropped and the name goes to the memory review queue. *Reason:* the story-memory addendum; name matching was behind V159/V169-style bugs.
- **D-14 Choice fast path.** Each choice carries a pre-classified, validated intent; clicking it skips the intent call, so the turn makes one call. Combat beat buttons also skip it. Typed input still makes two calls. *Reason:* halves requests for the most common turn without letting narrative contradict dice (the engine still resolves before narrating). Approved by Jared.
- **D-15 Per-turn response schema.** The response schema contains only the events legal in the current state. *Reason:* fewer schema tokens and within Gemini's schema-complexity limits.
- **D-16 Retry policy (Jared).** One automatic fresh retry only when the narrative reply is truncated (finishReason at the output limit), with a larger output budget, counted in the usage meter, and switchable off in settings. Every other failure (invalid JSON, rate limit, network) shows an error with a Retry button and makes no automatic call. Every retry reuses the same pre-rolled dice and engine results. Partial replies are never stitched. Reconciles phase1-answers Q57 with the story-memory addendum: "no continuation or recovery calls" means no stitching.
- **D-17 Story memory split and chapter summaries.** Memory state (facts, chapters, arc, pins, review queue) is the `memory` feature; retrieval, scoring and chapter-close policy are pure code in `src/memory/`. Chapter tags are computed by code from applied events, not written by the AI. The chapter summary and the arc summary come from the same light-model call at chapter close. Defaults: close on a major location change, a skip of 7+ days, `sceneEnded` with 8+ turns, or 30 turns. *Reason:* keeps facts code-owned and keeps the call budget at one extra light call per chapter.
- **D-18 Staleness fallback choice.** If the staleness detector requires a forward jump and the AI's choices have none, code appends a deterministic "Skip ahead: <top open thread>" choice and logs it. Suggest only, never auto-skip. Approved by Jared. *Reason:* the rule must hold without trusting the AI, and this is a code-generated option, not a repaired event.
- **D-19 Pacing and memory defaults.** Pacing ranges per turn: moment 5 s-15 min, scene 15 min-12 h, montage 1-120 days, timeSkip 7 days-10 years. Settling-in 14 in-game days; staleness 21 days; chapter max 30 turns. All config values. Approved by Jared as starting defaults.
- **D-20 No skill-tier gates (Jared).** Removes the progression addendum's rule that entering a new skill tier needs a milestone flag and that "XP accumulates while gated". Gating already exists where it should: lightsaber forms through the drill ceiling (25 + E), combat Force abilities through combat integration, teaching through the teacher factor. Physical stats and non-combat Force abilities have no gates. Crossing a tier (21, 41, 61, 81, 101) triggers a short, non-blocking milestone beat: code detects it and the next scene acknowledges it (a master's recognition, Temple reputation, a fact record). It never holds back XP or levels. Ranks keep their gates as ranks.md defines.
- **D-21 Speed multipliers stay as specified (Jared).** The progression addendum's list (focus, domain talent, teacher quality, real combat experience, multiplied, capped ~4x) is not used. M = talent x cross-talent x instruction x age x state of mind x alignment, capped at 2.8 (progression-numbers.md sec 5). Focus comes from hours and weights; combat experience comes from combat XP, E and CI (combat-xp.md sec 4). Total pace is capped at 4.0x the Average profile.
- **D-22 Roll divisor.** rolls.md (d20 + effective level / 10) supersedes v170-audit.md's "d20 + level / 4" wording. *Reason:* rolls.md is the decided spec, with tables and tests built on /10.
- **D-23 Integer dates.** The clock stores an absolute GSC day (signed; BBY negative) and a minute of day. No date strings in state; age, weekday and labels are derived. *Reason:* fixes the V170 string-parsing date bugs (BUG-026 and 13-calendar-and-time.md) at the root.
- **D-24 Settings and usage outside GameState.** API key, model choices, limits and the usage meter live in localStorage, not in saves. *Reason:* they belong to the device, not the campaign, and the key must never be exported.
- **D-25 Training budget interpolated by age (approved, Golden Rule 7).** Replaces the 3-row step table in training-routines.md sec 2 (12 and under / 13-17 / 18+) with a linear interpolation through the same values (anchors at ages 10, 15 and 20, flat outside), so a birthday never jumps the budget. Same targets and tests.
- **D-26 Token estimates.** The context builder estimates tokens as characters / ratio, calibrated per model from Gemini `usageMetadata`; no countTokens request. *Reason:* the request budget.
- **D-27 No credit events before the equipment spec.** CREDITS= has no v2 event until the equipment spec (M8) defines prices and the economy. Approved by Jared.
- **D-28 Build order replaces the pack's Phases 3-8 (Jared).** The M1-M9 milestones in architecture.md sec 15 replace the prompt pack's Phases 3-8. Each milestone is its own session: plan mode, then build. The pack prompts and the specs are checklists for the matching milestone. Each milestone ends playable locally (`npm run dev`), tested and committed on the `rebuild` branch. Nothing deploys to GitHub Pages until the Phase 9 cutover; the deploy workflow keeps its main-only trigger.
